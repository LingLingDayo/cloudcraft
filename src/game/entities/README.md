# 生物与实体架构规范

`entities` 负责可更新世界实体的领域模型、生物行为状态、运动能力组合、物种定义与版本化快照。该模块不得把具体物种判断散落到 `AnimalManager` 或渲染循环中。

## 分层职责

- `Entity` 定义实体身份、位置、速度、生命值和持久化入口。
- `Animal` 组合 `BehaviorStateMachine` 与 `MovementModeController`，统一执行行为决策、运动求解和表现同步。
- `behavior` 提供支持父状态的 HFSM。状态进入、更新、退出和转移必须由状态机调度。
- `movement` 提供运动模式注册表与优先级选择器。地面、游泳、飞行等能力通过模式组合，而非物种继承层级实现。
- `species` 保存物种工厂、生成权重、栖息地偏好和运动模式列表；运行期只依赖 `SpeciesDefinition`。
- `EntitySnapshot` 是存档数据载体，存储层不得直接序列化 Three.js 对象或行为实例。

## 生物扩展契约

新增物种时必须：

1. 新增继承 `Animal` 的物种类，并在构造时将物种定义提供的 `movementModeIds` 传给基类。
2. 在 `CoreSpecies` 或独立扩展包中注册 `SpeciesDefinition`，通过栖息地权重控制生成。
3. 使用 HFSM 状态表达捕猎、逃跑、休息等行为；禁止在全局管理器中增加物种类型分支。
4. 将需要恢复的行为状态和运动模式写入实体 `customData`，并保持对旧字段缺失的兼容。
5. 为生成选择、状态转换、运动模式优先级和快照恢复增加目录级测试。

`Pig` 已直接迁移到该契约：构造函数必须接收运动模式集合，不保留旧 Pig API 兼容层。`Leopard` 使用同一底座注册林地栖息偏好和攻击人类的行为状态。未来物种不得要求底座识别其类名。

## 运动模式扩展

`MovementMode` 通过 `canHandle(context)` 声明当前环境是否可用，通过 `update(context, deltaSeconds)` 修改复用的运动上下文。注册顺序代表选择优先级；切换模式不得创建每帧临时对象。

新增运动方式时只新增模式实现并注册稳定 ID，再由物种配置组合该 ID。核心运动控制器、`Animal` 更新管线和其他物种文件均不应修改。

## 生命周期与性能红线

- 高频 `update()` 禁止创建临时向量、集合或闭包；运动上下文和尺寸对象由生物实例复用。
- HFSM lineage 与运动模式实例必须在注册或配置变更时解析并缓存；逐帧更新只遍历缓存，禁止重新构造数组、`Set` 或查询注册表。
- HFSM 的 `dispose()` 必须退出当前状态；拥有几何体、材质、监听器或计时器的实体必须提供对称释放路径。
- 实体遍历期间不得直接修改实体集合，新增和移除应由管理器在安全边界统一处理。
- 快照只保存稳定字符串 ID 和纯数据，不保存注册表句柄、类实例或渲染资源。
- `customData` 只能包含有限数字、字符串、布尔值、`null`、数组和普通对象组成的递归 `EntitySnapshotValue`，不得使用 `any`、Three.js 对象或循环引用。
- 创建快照时必须深拷贝扩展数据；恢复前必须一次性校验 Schema、实体数组、唯一 ID、数值范围和扩展数据结构，避免部分恢复或与运行态共享引用。
- 统一存档边界兼容 `0.2.x` 的裸 `SerializedEntityData[]`：恢复前先迁移为 Schema 1 `EntitySnapshot`，并将旧 `pig` 类型映射为 `cloudcraft:pig`。该迁移只存在于持久化边界，不得在 `Pig` 或物种注册表中保留双 ID API。
